BookManager ローカルAPI

eBookJapanとの購入済み照会・書籍登録・更新・表紙保存のためのローカル連携

（2026-10-18）

はじめに：BookManagerの起動中に限り、ブラウザーのUserscriptがBookManagerのデータへアクセスできます。BookManagerを終了するとAPIも停止します。

1. 何ができるの？

電子書籍サイトの作品について、BookManagerに登録した他社購入情報を確認したり、書籍情報をBookManagerへ登録・更新したりできます。今回のコードには一括購入済み照会と表紙画像のアップロード処理も含まれています。

  • 購入済み確認：該当電子書籍サービス以外に同タイトル・同巻の登録があるか照会
  • 一括確認：複数タイトル・巻数をまとめて照会し、一覧表示を高速化
  • 書籍の検索・登録・編集：タイトル、著者、出版社、ラベル、サービス、URL、状態など
  • 表紙保存：画像をbase64で送信し、BookManagerのimages/へ保存

2. 導入・動作確認

  1. BookManagerを起動します。ローカルAPIはアプリ側のライフサイクルに従って起動・停止します。
  2. ブラウザーにUserscript管理拡張（例：Tampermonkey、Violentmonkey）を導入し、対応する電子書籍サービス連携スクリプトを有効にします。
  3. ブラウザーで http://127.0.0.1:8765/api/health にアクセスして稼働確認します。
{"ok": true, "service": "BookManager"}

標準の待受先は 127.0.0.1:8765 です。外部PC向けの公開サーバーではありません。

4. 他社購入済み確認

GET /api/book-status

GET http://127.0.0.1:8765/api/book-status?title=サンプル作品amp;volume=30
{
  "found": true,
  "title": "サンプル作品",
  "volume": 30,
  "services": ["電子書籍サービス"]
}
  • titleは必須。Unicode NFKCや空白・記号の差などを吸収した正規化比較を行います。
  • volumeは0以上の整数。省略した場合は巻数が設定されていない本を検索します。
  • eBookJapanとして登録されたサービスは照会結果から除外します。
  • ここでのfoundは照合条件を満たす他サービスの登録が存在することを表し、購入状態（status）までは確認していません。

POST /api/book-status/batch

除外フィルター等で、複数作品をまとめて照会するためのエンドポイントです。

POST http://127.0.0.1:8765/api/book-status/batch
Content-Type: application/json

{
  "items": [
    {"volume": 30, "titles": ["サンプル作品", "サンプル作品 30"]},
    {"volume": 5, "titles": ["サンプル作品"]}
  ]
}
{
  "results": [
    {"found": true, "services": ["電子書籍サービス"], "matched_title": "サンプル作品"},
    {"found": false, "services": [], "matched_title": null}
  ]
}

制約：リクエスト本文は256KiB以下、itemsは最大1000件、各項目のtitlesは最大20件です。照合されたmatched_titleはコード内部で正規化された文字列です。volumeが無指定の場合、現行の一括処理では一致行を取得しません。

5. 書籍の検索・詳細取得

GET /api/book?title=...&service=...

GET http://127.0.0.1:8765/api/book?title=サンプル作品&service=ebookjapan
{"matches": [{"id": 123, "title": "サンプル作品", "volume": 30, "series": "サンプル作品"}]}

上記の値はレスポンス形式の例です。titleは部分一致、serviceを指定した場合はサービス名で絞り込みます。GET /api/book/{id}はbooksテーブル内の該当行をJSONとして返します。未登録のIDは404です。

6. 新規書籍登録

POST /api/book

POST http://127.0.0.1:8765/api/book
Content-Type: application/json

{
  "title": "サンプル作品",
  "volume": 1,
  "series": "サンプル作品",
  "author": "著者名",
  "publisher": "出版社名",
  "label": "レーベル名",
  "service": "ebookjapan",
  "url": "https://ebookjapan.yahoo.co.jp/books/…/",
  "status": "未読",
  "open_target": "url",
  "cover_path": "images/ebj_example.jpg",
  "memo": ""
}
HTTP 201
{"id": 123, "message": "created"}

登録可能な主な項目はtitle / volume / series / author / publisher / label / service / url / cover_path / bookCd / book_cd / open_target / status / completed / favorite / memoです。titleは必須。cover_pathはimages/に続く許可文字列に制限されます。tagsやimageFileも入力を受け取る記述がありますが、新規登録処理ではタグ関連付けと画像URLの保存は実施していません。

同一タイトル・巻数・サービスの候補が見つかった場合は新規登録せず、HTTP 400でduplicate_found、既存のidなどを返します。内部ではLIKEを使った検査である点に注意してください。

7. 既存書籍の更新

POST /api/book/{id} または PUT /api/book/{id}

PUT http://127.0.0.1:8765/api/book/123
Content-Type: application/json

{"title": "サンプル作品", "status": "読了", "memo": "更新例"}
HTTP 200
{"updated": true}

現行コードでは指定された一部フィールドだけを更新します。volumeは更新対象に含まれていません。また、imageFile等の一部入力は実際のDB列と一致しない可能性があるため、表紙変更には/api/cover/uploadで保存した相対パスをcover_pathとして使用してください。

作成・更新が正常終了した際には、BookManagerのサービスオブジェクトがある場合、画面更新イベントを発行する処理があります。

8. 表紙画像のアップロード

POST /api/cover/upload

画像のバイナリをbase64でエンコードし、image_base64として送信します。画像URLを直接送信するAPIではありません。

POST http://127.0.0.1:8765/api/cover/upload
Content-Type: application/json

{"image_base64": "（画像をbase64化した文字列）"}
HTTP 201
{
  "saved": true,
  "cover_path": "images/ebj_0123456789abcdef01234567.jpg",
  "filename": "ebj_0123456789abcdef01234567.jpg",
  "saved_at": "（保存先の絶対パス）"
}

保存先はBookManagerプロジェクト直下のimages/です。JPEG・PNG・GIF・WebPを画像先頭のシグネチャで判別します。本文12MiB以下・デコード画像8MiB以下の制限があります。同一内容はハッシュ名で再利用されます。返されたcover_pathを新規登録または更新APIへ渡してください。

9. 呼び出し元・ブラウザー連携

コードにはeBookJapanとDMM関連ドメインのOrigin許可設定があります。CORSはGET / POST / PUT / OPTIONSに対応し、事前リクエストではContent-Typeを許可します。許可されていないOriginからの要求には403を返します。

Userscript管理拡張では、通信方式に応じて@connect 127.0.0.1等の許可が必要です。ブラウザーや拡張機能の設定により挙動が異なる場合があります。

BookManagerを起動していない場合、Userscript側は接続失敗を処理し、通常の電子書籍サイト閲覧を妨げないようにしてください。

10. 実装上の注意（アップロード版コードで確認）

重要：ここはAPIの動作保証ではなく、アップロードされたPython実装との照合結果です。HTMLの編集だけではPython側の問題は解消しません。
  • 表紙・タグのサブルート：/api/book/{id}/imageと/api/book/{id}/tagsは{id}として123/image等を整数変換してしまうため、現状は正しくルーティングできません。
  • DELETE：do_DELETE_tagsの補助関数はありますが、HTTPのdo_DELETEは定義されていないため、タグ削除APIは使用できません。
  • 巻数更新：POST/PUT /api/book/{id}の更新可能フィールドにvolumeが含まれていません。
  • 重複判定：検索にはLIKEが使われる箇所があり、厳密な完全一致ではありません。入力によって過検出する可能性があります。
  • 一括照会：POST /api/book-status/batchは正常にルーティングされますが、status（未購入など）に基づく所有判定は行いません。
  • 更新入力：imageFileを更新対象の列名として扱う処理があり、DBの列構成によっては更新エラーになります。

11. エラー形式

エラーは原則JSONで返ります。例：{"error":"title_required"}、{"error":"invalid_json"}、{"error":"database_error"}、{"error":"origin_not_allowed"}。重複時はcode: "duplicate_found"など追加情報を返します。400、403、404、413、500などのHTTPステータスを使用します。

この文書はアップロード版 local_api.py の静的コード確認に基づく説明です。実環境のBookManagerデータベースやUserscriptとの結合テストは行っていません。
